# WSHS Web Display — confirmed schema v2 update

Source-complete for the supplied 2026–27 handoff. Validation covered source,
syntax and static data parity only. No application resolver, browser, build,
automated UI test, simulator, deployment, commit, push, production session or
browser storage operation was executed. Live countdowns, migration/persistence
round trips, layout and end-to-end native imports remain untested.

## Files changed in this update

- `public/builtins/wshs/wshs.json`: byte-for-byte schema-v2 handoff copy.
- `wshs-source.mjs`: generated synchronous copy of exactly the same data, used
  for compatibility overlays without a network request or asynchronous store
  migration. It must stay equal to the JSON when the handoff is refreshed.
- `wshs.mjs`: v2 adaptation, semester preference resolution, selective v1 update,
  conflict records and WSHS correction compatibility.

  snapshots and integrates existing lunch helpers.
- `school-setup.mjs`: WSHS preview uses attendance start when no rotation anchor
  exists. Other schools keep their existing preview path.
- `app.js`: semester-one/two selectors, live effective-choice text for the viewed
  date, preserved-conflict notices, and corrected WSHS settings copy.
- `docs/wshs-2026-2027.md`: this report and manual checklist.

The earlier, uncommitted WSHS addition remains in the worktree. This update did
not additionally edit `profile-store.mjs` or the WSHS profile manifest. No existing
school resources, styles, HTML, shared presentation engine, timing-overlay module,
or Apple source files changed during this update.

## Data integration and semester behavior

Authority: `../SchoolSource/WSHS/2026-2027-handoff.json`,
`handoffSchemaVersion: 2`, `contentVersion: 2026-2027.2`. The handoff schema is
separate from the unchanged native snapshot schema 1, native interchange format
2, Web config schema 2 and Display backup format 1.

The adapter reads every template, all 15 confirmed date exceptions, exact common
rows, lunch/class alternatives, item labels, closure ranges, bounds and make-up
dates from that data. Special templates retain the same stable indexed item IDs
as Apple, including repeated P7 rows. It adds only the necessary nonassignable
Break period definition; no dates or times were inferred.

January 6, 2027 starts semester two. P5 and P6 retain separate semester-one
preferences. Semester two independently derives L1→L2 or L2→L1 unless its nullable
explicit override is L1/L2. Choosing Automatic clears that period's explicit
semester-two override. Resolution compares dates without saving or rewriting
choices, including on an activated May 26 make-up day after ordinary attendance
ends. Ordinary school dates remain August 10–May 25.

Old Web profiles save first choices in `portable.shared.assignments.all`; their
retained `wshsSource` identifies that representation. Native portable snapshots
use the canonical `regular` P5 and `wednesday` P6 rules' `selectedOptionID` and
`secondSemesterOptionID`, matching Apple's preference ownership. Explicit Web
semester edits live in optional `portable.shared.wshsLunchPreferences`, using the
same two-field preference shape. Changing a first choice also updates its old
assignment lunch for compatibility. Native fields, original handoff metadata,
other assignments and unrelated preferences remain intact.

Display Settings and Edit Schedule show both semesters for P5/P6, the automatic
result, and effective lunches for the currently viewed date (or today). The
resolved template decides the actual selector: December 15 and May 20 use P6;
May 19 uses P5; all half-day exam templates have no lunch.

## Existing profiles, precedence and conflicts

Normalization overlays recognized `2026-2027.1` and `2026-2027.1-edited` WSHS
snapshots in memory, including existing profiles, single/collection backups and
native portable imports. It adds missing special templates/rules and Break;
adds missing confirmed date exceptions; replaces only the exact stock pending
placeholder shape (`scheduleUnavailable` plus the known pending note and no
additional metadata); and updates the stock January 6 note. Regular templates,
user date exceptions, source/template edits, profile IDs, names, assignments,
local display edits, calibration, timing overrides and calendar corrections are
retained. Stock source version changes to `.2` (retaining `-edited`); original
export/source provenance remains available in its original metadata.

No storage write occurs just to read an old profile or change the viewed date.
The existing atomic save path writes the upgraded profile on a later authorized
profile/store edit. Exports contain the normalized version. No new storage key,
backup envelope or reset is required. Reload/import behavior is source-wired but
has not been exercised in a browser.

Precedence follows the handoff:

1. Profile `noSchool` correction.
2. Profile `schoolInSession` correction restores the ordinary weekday template
   for that exact day, bypassing attendance bounds only on the corrected day.
   Use only when ordinary bells are confirmed; it does not install special bells.
3. Preserved user date-specific definition exception.
4. Confirmed source exception, replacing only absent/stock-pending records.
5. Ordinary weekday template within attendance bounds.

Existing custom records are never silently replaced to force source parity.
Preserved collisions are recorded in `wshsUpdateConflicts` and shown in settings;
thus a custom exception can intentionally differ from the source timetable.
Matching custom template/rule IDs also remain and are flagged. Local display
names and timing overlays retain priority and may intentionally alter source
labels/times. Actual browser profiles were not read, so no assertion is made
about which user-specific conflicts exist. Unknown source versions are retained
without a forced source replacement.

WSHS `noSchool` and `schoolInSession` corrections are now accepted on valid dates
with profile/date/ID checks, including already-authored corrections on exam dates.
Rotation correction kinds and other schools keep the prior import restrictions.
May 26 remains closed until explicitly activated; activation resolves ordinary
Wednesday bells with semester-two P6 lunch. May 27 remains outside the year.

## First Bell, breaks and completion

Only `regular`, `wednesday`, and `thursday` allow the ordinary 07:15 First Bell.
October 9 and March 12 explicitly use regular and retain it. Every special
exam/seven-period template, including a future custom template, suppresses this
point even if an old snapshot lacks new exclusions. Preserved explicit point
exclusions still apply. Instruction starts at 07:20.

Breaks are the supplied visible duration activities, not point bells or synthetic
passing periods. Their source intervals are retained and marked
`bellAlertEligible: false`. Like Apple, a supplied break may be the current
activity during its actual interval; no extra transitions fill the surrounding
published gaps. Web Display has no new alert/notification path. The unchanged
presentation engine handles active intervals, neutral gaps, current/next,
countdowns and completion. No runtime guarantee is claimed for those paths.

All six half-day templates contain only the two named exams and supplied break;
no regular classes, lunch or First Bell is appended. Their last exam ends at
11:40. May 19 finishes at 13:20; the exam-Wednesday schedule at 13:18; the other
full special templates at 14:20.

## Remaining limitations

Nicole's additional state-testing schedules are unknown; none were invented.
A future confirmed dedicated template plus a scheduled date exception can be
resolved through the existing snapshot path, but there is no general-purpose
Web date-template editor. A `schoolInSession` correction only restores ordinary
weekday bells. A future school-source addition needs a reviewed compatibility
update for already-saved snapshots; changing the bundled JSON alone cannot
replace arbitrary saved/custom snapshots. Other native correction kinds remain
unsupported. Custom source overrides can intentionally defeat published parity
and need review where settings report conflicts. Make-up activation/bell patterns
and the source's conflicting group wording remain provisional; semester switching
and all supplied exams/early dismissals are confirmed.
